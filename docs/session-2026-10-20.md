# Session log: 2026-10-20

First run of the workflow, on "Attention Is All You Need" (Vaswani et al., 2017).

## Goal

Follow a LinkedIn post's workflow for understanding papers: NotebookLM notebook with the
paper and background reading, then a long audio overview with a teaching prompt. Start by
confirming the tools are present and installing the missing ones.

## Tool check

| Step | Needed | Found |
|---|---|---|
| Paper | the PDF | present |
| 1. Add to NotebookLM | a way to drive NotebookLM | missing |
| 2. Background reading | web search/fetch | Claude Code does this; ChatGPT/Gemini not needed |
| 3. Audio overview | NotebookLM audio | missing (depends on step 1) |
| 4. Listen | audio file, ffmpeg | present |

Options considered for the gap: `notebooklm-py` (CLI, chosen), `notebooklm-mcp-cli` (MCP
server), or doing steps 1 and 3 by hand in the browser.

## What was done

1. `uv tool install notebooklm-py`, then reinstalled with the `[browser]` extra because
   `doctor` reported Playwright missing. `notebooklm --profile default doctor --fix` created
   the profile directory.
2. Sign-in, which took three attempts:
   - Typed `  ! notebooklm login --browser chrome` with leading spaces, so Claude Code sent
     it as a message instead of running it.
   - Ran from a background shell; the Chrome window was closed before login was detected
     ("The browser window was closed during login").
   - Ran with `!` directly; it outlived the 120 s foreground timeout, moved to the
     background, and succeeded. Signed in with a personal Gmail account.
3. `notebooklm create "Attention Is All You Need" --use`, then `source add` for the PDF.
4. Checked nine background URLs with curl (the YouTube one first failed because zsh globbed
   the `?`), then added them. All ten sources reached `ready`. The list is in
   `sources/attention-is-all-you-need.txt`.
5. `notebooklm generate audio --prompt-file ... --format deep-dive --length long`, then
   `artifact wait` and `download audio`. It took about an hour, and the result was titled
   "How the Transformer Architecture Works" and ran 50:51.
6. The downloaded `.mp3` was really AAC (256 kb/s) in an MP4 container, 98 MB. Renamed it to
   `.m4a` and converted it with `ffmpeg -c:a libmp3lame -q:a 4` to a real 34 MB MP3.

The prompt was the post's prompt with one typo fixed ("experiments.Whenever"); it is in
`prompts/student-walkthrough.txt`.
